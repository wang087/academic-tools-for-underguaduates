## 阶段 S：学部/学院官网导师抓取（唯一数据源）

### 硬性规定：只从**学部/学院官网**取，不用学校教师主页系统

学校教师主页系统（`faculty.ustc.edu.cn`、`person.zju.edu.cn` 等）有两个硬伤：

| 问题                                                 | 后果                                                                     |
| ---------------------------------------------------- | ------------------------------------------------------------------------ |
| 只登记**已在系统里维护主页**的教师，覆盖面不全 | 学院官网另有其人，名单从源头就缺人                                        |
| 大量页面**根本没有「研究方向」栏位**           | 过半数页签存在但内容是 `<p>暂无内容</p>`，方向字段大面积空转       |

（两处的具体人数见 [实测结果汇总.md](实测结果汇总.md#s-1)。）

学部/学院官网的师资页由**学院自己维护**，方向/邮箱/职称常**直接写在列表页上**，
新鲜度与完整度都更好。**因此本流程统一以学部官网为准。**

### 用法

```bash
# 看有哪些学校/学院可选
uv run python scripts/harvest_faculty.py --list-units

# 全量抓取（列表 → 详情 → 归类 → 报告）
uv run python scripts/harvest_faculty.py --unit zju --out outputs/06_浙大生科院
uv run python scripts/harvest_faculty.py --unit ustc:life-med --out outputs/01_导师名单

# 只抓列表（快速核对人数）
uv run python scripts/harvest_faculty.py --unit zju --stage=list
```

`--unit` 接受三种写法：学校 key（`zju`）、`学校:学院`（`zju:life-sci`）、
中文名/别名（`浙大`、`浙江大学生命科学学院`）。

### 任意院系官网：运行时发现与解析（默认）

给定院系官网入口，使用同站有界导航发现、语义表格、个人卡片及已有家族引擎择优解析。
`templates/学部官网源.json` 是可选的已知站点预设，不是学校白名单，也不是新站点运行的前置条件。

```bash
# 院系官网入口：发现下级师资目录后进入正式列表/详情/归类链路
uv run python scripts/harvest_faculty.py --site https://chem.ustc.edu.cn/ --stage list

# 已知师资列表页：直接抓取，无需登记学校或引擎
uv run python scripts/harvest_faculty.py --url https://www.hfuu.edu.cn/aibd/7262/list.htm --stage all

# 探查与证据输出；--dry-run 仅打印，不写文件
uv run python scripts/faculty_discover.py --site https://szb.jmu.edu.cn/szll/szdw.htm --dry-run
uv run python scripts/faculty_discover.py --url https://chem.ustc.edu.cn/js/list.htm --explain

# 已有站点预设仍可复用
uv run python scripts/harvest_faculty.py --unit ustc:chem --out outputs/ustc_chem
```

- `--site` 用于院系首页或教研室人员文章目录；`--url` 用于明确的名单页。
  `faculty_discover.py --site URL --direct` 与直接名单探测同义。
- 正式抓取按 URL 的主机名和哈希隔离输出，保留名单、逐页证据、发现路径及来源页面。
  同一输出根下测试不同站点或栏目不会相互覆盖。
- 自动发现最多两层、限定同站链接；分页仅跟随真实下一页链接，`--max-pages` 控制上限。
  缺页、失败、同名异链接、未支持目录或无总条目数时如实保留覆盖缺口，不猜测分页地址。
- 退出码：`0` 解析通过，`4` 待核验/部分结果，`3` 没有可用名单；
  `0` 不代表全院覆盖，必须同时查看 `coverage`、`scope`、`partial` 和逐页证据。
- `verdict=accept` 只表示当前结构可解析；`coverage=verified` 要求在声明范围内遍历完成且
  条目总数精确对账、无身份歧义。官网“共N条”是记录数，不能直接当作唯一在职人数。
- 完整研究方向与截断摘要分开：截断内容仅放 `direction_hint`，仍需详情补全；
  不从栏目名推断职称、方向、导师资格或在职状态。
- 默认预设文件缺失时仍可运行通用解析。显式 `--config` 路径无效或内容损坏时应报错。
  仅在需要长期复用且核验通过后，才用 `faculty_discover.py --site ... --write` 保存预设。

#### 站点家族（`scripts/faculty_engines.py`）

新增学校的**唯一难点**是"这站的师资页长什么样"。实测中国高校院系官网
集中在少数几个站群家族，故把判据集中在引擎库里，**新增学校不必改脚本**：

| 家族                 | 结构指纹                                                        | 方向在哪          | 已验证站点                                      |
| -------------------- | --------------------------------------------------------------- | ----------------- | ----------------------------------------------- |
| `wp_news_list`     | `span.news_title > a[title]`，`id="wp_news_wN"`             | 常在 title 括注里 | 中科大化学系、复旦生科院、南大化学              |
| `wp_newsinfo_card` | `li.itemhover` + `div.tit`                                  | 详情页正文        | 中科大生医部                                    |
| `wp_teacher_card`  | `li.list-item` + `h3` + `span.direction` + `span.email` | 列表页直接有      | 浙大生科院                                      |
| `generic_cluster`  | **无固定 class**：按人名链接的 **URL 形态聚类**     | 详情页正文        | 上海交大生科院                                  |
| `tsites_list`      | 学校教师主页系统（`faculty.*.edu.cn`）                        | 详情页            | 兜底，非首选                                    |
| `render`           | 整页 JS 渲染后，再走上面任一解析                                | 详情页正文        | 需无头浏览器（`faculty_render.py`）           |
| `interactive`      | **点击分类**后异步加载                                    | 详情页正文        | 南京大学化学化工学院（`faculty_interact.py`） |

`generic_cluster` 是**结构无关**的兜底：不依赖任何站点特有 class，
只锚定"形如人名的链接"，再按 URL 形态聚类取最大簇 ——
导航结构和栏目词须先过滤；不能仅凭链接形态认定教师身份。

后两个家族是**直连失败后的转 CDP 分支**（§5.1）：前者适用于
"渲染一下就有"的 SPA 外壳站，后者适用于"必须点击才加载"的站群。

#### 解析置信与覆盖范围分开核验

`select_parser` 比较通用 DOM/表格及站点家族候选，返回 `accept/review/reject`。
导航、普通课程表、错误页不能作为人员名单；多个解析候选发生冲突时保留证据供核验。
`collect_page` 在真实分页汇总后核对官网声明条目数；乘法估计不能代替逐页对账。
小名录没有总数时可以有可用记录，但 `coverage` 仍为 `unverified`。
按教授、教研系列、ALL等标签取得的名单只覆盖对应栏目，不能称全院或全校完整名单。

#### JS 渲染站：不再直接放弃，转 CDP 浏览器链路

有些站的师资页是**空壳**，教师数据由 JS/AJAX 拉取（实测：南京大学化学化工学院
`ul.teacher-list` 为空）。直连只能拿到 0 人。

按 §5.1「第一层失败**转 CDP**」，阶段 S 备有两级浏览器链路：

| 家族            | 何时用                         | 实现                                                           |
| --------------- | ------------------------------ | -------------------------------------------------------------- |
| `render`      | 整页渲染后即可解析             | `faculty_render.py` → `robot/crawl_site.py`（无头浏览器） |
| `interactive` | 数据靠**点击分类**才加载 | `faculty_interact.py`（CDP 点击枚举）                        |

**南京大学化学化工学院**是 `interactive` 的实例：11 个学科链接全是
`javascript:void(0)`，其 AJAX 端点对非浏览器客户端返回 **503**，
**渲染也只能出默认的院士 3 人，逐一点击才出 236 人**。

```bash
# 已收录：直接跑（自动走浏览器链路）
uv run python scripts/harvest_faculty.py --unit nju:chem --out outputs/nju_chem
```

> **`interactive` 的前置条件（硬约束，必读）**
>
> 启动环境限制须按实际日志诊断；uv/venv不作为必然失败判据。统一使用通用浏览器池并核验DOM。

若站内确实没有形如「师资队伍/教师名录」的入口，用 `--url` 直接指定具体页。

#### 离线自检（改引擎后**必跑**）

```bash
uv run python scripts/selftest_engines.py
uv run python scripts/selftest_faculty_dom.py
uv run python scripts/selftest_faculty_discovery.py
```

离线夹具覆盖站群骨架、通用 DOM、无预设入口和发现/分页契约，测试数据在代码中合成，不依赖真实作者样例包：
无个人主页的教师被漏掉、导航链接混入、`研究方向` 锚点在导航里、
`共N条` 对账失效、`listN.htm` 分页、JS 空壳识别，
以及浏览器家族（枚举结果解析、非人名过滤、预启动命令含
`--remote-allow-origins`）等。

### 新增一所学校：手工配置（探索模式，仍受支持）

人工预设是可选适配方式。优先使用运行时发现；遇未支持结构时先核对页面证据，再决定是否保存配置：

```json
"xxx": {
  "name": "XX大学",
  "alias": ["XX大"],
  "units": {
    "life-sci": {
      "name": "生命科学学院",
      "base": "https://bio.xxx.edu.cn",
      "list_type": "wp_teacher_card",
      "sections": [
        { "name": "教授", "path": "/szdw/js/list.htm", "paging": "auto", "detail": "star" }
      ]
    }
  }
}
```

- `detail: "star"` —— 列表页**已含**方向与邮箱（浙大生科院所属），不进详情页
- `detail: "fetch"` —— 列表页只给姓名+链接，须进详情页抽（USTC 生医部所属）

### 两种列表模板（`list_types`）

| 模板                 | 结构                                                                                    | 已验证站点                               |
| -------------------- | --------------------------------------------------------------------------------------- | ---------------------------------------- |
| `wp_teacher_card`  | `<li class=list-item>` + `<h3>姓名 职称</h3>` + `span.direction` + `span.email` | 浙大生科院`www.cls.zju.edu.cn`         |
| `wp_newsinfo_card` | 列表只给姓名+链接，方向在详情页正文                                                     | 中科大生医部`biomed.ustc.edu.cn`       |
| `engine_dispatch`  | **复用模式**：`section.engine` 指定家族，规则在 `faculty_engines.py`          | 中科大化学系、复旦生科院、上海交大生科院 |

> `engine_dispatch` 是**复用模式的落点**：配置里只写「引擎名 + 页面路径」，
> 不写站点特有 class。上面 `faculty_discover.py --write` 生成的就是这种条目。

> **已验证覆盖的学校 / 院系 / 家族 / 人数、以及抓取耗时基线**：见
> [实测结果汇总.md](实测结果汇总.md#s-5)（S-5 复用模式覆盖情况、S-6 抓取基线）。
> 本文件只留判据与坑，不留运行数据（顶部硬性要求第 7 条）。
>
> 两条**定性**结论留在这里，因为它们直接决定怎么做：
>
> - 空壳站（名录页 `ul.teacher-list` 为空、学科需逐一点击）**直连与单纯渲染都只能得个位数**，
>   必须走 `interactive` 经 CDP 逐一点击，再由标准脚本抓各人主页补方向。
> - 复用模式与浏览器链路引入后，走既有解析路径的学校人数**与引入前完全一致** ——
>   即改动是纯增量，没有影响既有学校。

### 抽取实现的坑（都踩过）

| # | 坑                              | 症状                                                      | 正确做法                                                   |
| - | ------------------------------- | --------------------------------------------------------- | ---------------------------------------------------------- |
| 1 | 容器懒匹配`(.*?)</div></div>` | 正文只剩 5 字                                             | 按**标签配平**取容器                                 |
| 2 | 线索词表不全                    | 漏掉「主要研究方向**及内容**」「研究方向」独立成行  | 线索词要含变体与**行尾无冒号**的独立标题             |
| 3 | 编号条目后遇非编号行就停        | 毕国强 3 条只抽到 1 条                                    | 条目后的说明段**不该中断扫描**                       |
| 4 | 姓名未去职衔/标记词             | 出现「徐平龙 （兼聘）」「林爱福 长聘」「徐程 高级」       | 用**长词优先**的职称表 + 单独剥离 `兼聘/长聘` 标记 |
| 5 | 姓名字间空格未规范              | 站点排成「周 琦」，与「周琦」重复计数                     | 两字中文名合并空格（英文名保留）                           |
| 6 | 相对 URL 未补主机               | `/clscn/2022/…/page.htm` 抓取失败、静默跳过            | 用`_abs_url()` 补全                                      |
| 7 | 跨栏目未合并                    | 同一人同时列在「人才队伍」与「研究所」，209 条只有 184 人 | 按姓名合并，方向取**并集**、栏目存 `sections`      |
| 8 | 分隔符不全                      | 「计算生物学 · 生物物理学」只按逗号切 → 与已拆形式重复  | 分隔符补 `·•・                                           |

### 清洗判据

- 多栏目名导航行：`科学研究 研究领域 论文成果 专利 著作成果 科研项目`
- 栏目名：`发表文章`、`招生招聘`、`基本信息`、`社会兼职`、`学位：博士`
- 论文列表：`Zuo X#, Zhao R#, Wu M#, …`；无中文的引文片段 `Duan Y, Young R, Schnabl B`
- 基金：`…（国家自然科学基金项目,中科院创新项目子课题）` → 只剥括号，**保留中文主干**
- 招生方向：`招生方向：细胞生物学，分子生物学…`（是招生口径，不是研究方向）

> **判据集中在 `harvest_faculty.is_direction` 一处**（`merge_roster.py` 直接复用它）。
> 不要在别的脚本里另写一套 —— 曾经判据漂移，导致 9 条残留漏网。

### [WARN] 清洗只能做一遍

踩过的坑：先跑 merge、再跑 clean、再跑更严格的 clean，**误差累积**，
把 190 人砍到 144 人（其中大量是误删）。正确顺序是
**恢复 → 合并 → 清洗**，在**一个脚本里一次跑完**；且
"清洗后为空"**不能**覆盖原有的 `no_direction_reason`
（否则会把"官网暂无内容"错写成"判定为导航行"）。

**产出物**（在 `--out` 目录下）：

| 文件                          | 内容                                             |
| ----------------------------- | ------------------------------------------------ |
| `roster_list.json`          | 全部教师（姓名 / slug / 主页 URL），按官网顺序   |
| `roster_detail.json`        | 每人 + 职称 + 研究方向原文 + 解析状态            |
| `mentors_grouped.json`      | 按细分方向归类的机读结果（供 agent 消费）        |
| `导师名单与方向归类.md`     | **给人看的报告**：分方向的表格，带主页链接 |
| `raw_list/` `raw_detail/` | 原始 HTML 存档（解析有疑问时人工核对）           |

**归类规则**：`templates/导师方向规则.json`（关键词子串匹配，可改）。
未命中任何规则的人进「未分类」桶 —— **脚本不会把人硬塞进某个方向**。

> [WARN] **归类是关键词粗分类，不是权威学科划分**；一位老师可能出现在多个方向下。
> 报告里每条方向都保留**主页原文**，务必提示用户以老师主页为准。

**本阶段结束时必须停下，等用户选择**：

把归类结果（方向 + 每方向的代表性导师）呈现给用户，并**等待其回复**。
脚本末尾会自动打印建议话术。要点：

- 列出各方向及人数，每方向举 3–8 位代表老师；
- 说明"也可以直接点名某位老师，或说你更关心的问题"；
- 明确告诉用户**这只是粗分类**，可点链接自己看老师主页。

用户选定后 → 进入阶段 R。

> **量级预期**：列表页整院抓完是**秒级**，逐人详情页是**分钟级**且可 0 失败；
> 有结构化「研究方向」栏位的通常约**半数**，其余页面确无该栏位
> （脚本如实标注，不臆造）。人数与官网自称条数应**逐项吻合**，
> 吻合才说明分页无遗漏。具体数据见
> [实测结果汇总.md](实测结果汇总.md#s-7)。
