### 阶段 K：知识图谱（overview / 词云 / 方向聚类）

> **闸门**：`uv run python scripts/prepare_stage.py --check K`
> （退出码 3 = 准备阶段 `make_graphs=no`）
>
> **位置是硬性的**：**所有搜集工作完成之后、PPT 制作之前**（H2 之后、P 之前）。
> 三张图都要吃「最终」产物 —— 解读卡、综述终表、review 结果；
> 早画出来的图，等后面补了数据就全过期了。

> **定位说明（v18）**：overview 是**「研究结构叙事图」**——作者→阶段→方向→综述的
> 归属树 + 方法外环，**不是**共现网络。它的距离表示层级归属，不表示主题相关性；
> 想要「按共现强度布局」的图，用 `keywords_three_layer.py --export` 导出的
> VOSviewer map+network（见下）。两者不要互相替代，也不要拿一张图去解释另一张。

> **依赖（硬依赖）**：本阶段需要 `matplotlib` / `networkx` / **`python-igraph`** /
> **`adjustText`** / **`wordcloud`**。缺任何一个都**直接退出码 2**并打印完整命令 ——
> **不产出降级图、不留半成品**。
> （`python-igraph` 自带全部布局算法，**不需要系统安装 Graphviz** ——
> 没有 `dot` 二进制也能出图。
> `wordcloud` 只在默认的 `--wc-engine=library` 下需要。）

```bash
uv run --with matplotlib --with networkx --with python-igraph --with adjustText \
       --with wordcloud python scripts/knowledge_graph.py
#    --format=auto（默认，SVG 优先、失败退 PNG）｜ --also-png 两种都要
#    --recent-years=3     方向聚类的「近 N 年」
#    --max-reviews=3      每个方向下最多挂几篇综述
#    --max-dirs=12 / --max-review-nodes=24   图上方向/综述节点的上限
#    --dpi=300            PNG 回退时的分辨率
#    --wc-engine=library|custom  词云引擎（默认 library＝wordcloud **自绘**；custom＝自研螺旋+矩形碰撞）
#    --wc-lang=both|zh|en 词云语言口径（默认 both；只要中文用 zh）
#    --wc-min-docs=3      **只来自方法描述**的词至少要出现在几篇论文里
#    --kw-model           词云中文留词再加一层 **kw 模型精筛**（默认关；只删不加，
#                         剔除词记入 graph_data.json 的 drop_reasons 可审计）。
#                         需 torch/transformers/peft —— 环境自检：
#                         python scripts/selftest_small_model.py
#    --strict-fonts       任一图在目标尺寸下低于 5 pt 就**硬失败（退出码 4）**，
#                         并指名哪张图哪个条目、低到多少（默认只 WARN，照旧出图）
```

#                         词的来源权重：文章关键词 > 题名 > 摘要 > 卡片方法描述


**三张图（用户指定）**

| #  | 图                 | 内容                                                                                                                                                                                                                                                                                                                    |
| -- | ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ① | **overview** | **径向整齐树**：作者在圆心 → 阶段（扇区）→ 研究方向 → 该方向最紧密的综述（橙点编号，完整题名在右侧清单）；**Louvain 社区**给方向层上色；方法词另置**外环**，两条方法关系紧密时沿环画一条**记忆连接**（有名字 + 一句由数据生成的原因）。**16:10 画幅、标题为「<作者名> 研究工作图谱」** |
| ② | **词云**     | 以作者为中心；**颜色区分研究方向**；**取词按「文章关键词 > 题名 > 摘要 > 解读卡方法描述」加权**，并剔除单位/试剂缩写、受控范式标签与跨词碎片（见下）                                                                                                                                                        |
| ③ | **方向聚类** | **时间线**：行 = 方向（行标签带近 N 年条数），x = 年份，点大小 = 被引，颜色 = 热点簇（样本不足的行不着色）。每个方向**近 N 年**的论文与热点                                                                                                                                                                 |

**overview 结构（v16.3 重写）**

| 环节                   | 做法                                                                                                                                                                                                                                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **层级位置**     | 交给`igraph.layout_reingold_tilford_circular`（径向整齐树）：根在圆心、每层等半径、子树扇区连续且宽度∝叶子数。**不再手搓角度**                                                                                                                                 |
| **标签避让**     | 交给`adjustText`，且**只移文字、不动节点**，带引线。旧版把两件事混在一起（推节点躲标签），结果径向层级被推没了 —— 渲染出来综述挤成左侧一团、方法漂到外圈                                                                                                      |
| **节点 vs 标签** | 节点画成**小圆点**，标签是可移动文字。旧版把标签做成药丸状节点本身，标签一动节点就动，避让无从谈起                                                                                                                                                                |
| **综述题名**     | 左图只放**编号**，完整题名进**右侧清单**（两栏）。旧版把题名截到 34 字符上云，**绝大多数被截成「…」**，整层不可读                                                                                                                                    |
| **方法层取词**   | 与词云**同一套筛选**（邻接熵 + 单位/标签/泛化词剔除）。旧版直接 `tokenize()`，**逾四分之一的节点是垃圾** —— `经元`/`鼠海`/`养基`/`谷氨` 这类跨词碎片，混着 `div`/`min`/`e18`/`kcl`/`student` 这类单位与来源噪声                                             |
| **记忆连接判据** | ① 禁「子串对」（`神经`↔`经元` 这类**词与自己的子串**配对）；② 共现 ≥3 篇；③ 按 **lift**（相对共现强度）排序，不是按原始共现次数；④ 单节点出度 ≤3、最多 8 条；⑤ 原因**逐条由数据生成**（共现篇数 + 年份跨度 + 方向分布），不再是同一句套话 |
| **记忆连接弧线** | **沿外环画短弧**，不画弦 —— 弦会穿过圆心压在树上（旧版画成弦时**全部弧线横穿画面**）。环序用**一维谱排序**（Fiedler 向量）让相连的方法相邻                                                                                                                   |
| **坐标落盘**     | 节点坐标写进`graph_data.json` 的 `overview_layout.pos`，布局**可事后审计**（旧版位置不落盘，"扇区式布局"被破坏了很久都没人发现）                                                                                                                              |

**方向聚类结构（v16.3 重写）**

旧版是「x=方向、y=年份」的散点 + 右侧冗余条形面板。两个硬伤：
x 轴只有 2 个刻度时散点退化、同年的点挤在一条水平线上靠固定 9 pt 错开；
右侧条形把"方向"编码在 y 轴上（散点却在 x 轴），两 panel 语义不一致且与 x 刻度里
已有的"(13 条)"重复。新版改为 **CiteSpace 式 timeline view**（行=方向、x=年份），
标签用 `adjustText` 避让并带引线；**热点簇只在 ≥4 篇时才着色** ——
哪怕只有 1 篇论文也会被算出"热点簇"，那种着色是噪声，样本不足的行一律灰色并明写原因。

**词云取词口径**

> **闸门**：不达标不出词，也不静默丢词 —— 逐条记录在报告的「词云取词与剔除记录」一节。

| 环节                       | 规则                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **来源优先级**       | ① 文章自带`Keywords`（权重 3）② 题名（权重 2）③ 摘要（权重 2，**仅在该篇既无关键词也取不到题名时**用）④ 解读卡方法描述（权重 1，量最大也最杂，作补充）                                                                                                                                                                                                                 |
| **关键词解析门**     | 从`interpret/tasks/<slug>.json` 的正文里解析 `Keywords` / `关键词` 段；**疑似把 Introduction 一起吞进来就整份丢弃**（宁可少一个来源，也不让散文上云）。解读卡若自带 `keywords` 字段则优先用它                                                                                                                                                                        |
| **中文筛词**         | 候选 2–4 字；要求**左右邻接熵 ≥0.9 bit 且频次 ≥3**。「小鼠海马→鼠海」「突触前→触前」「谷氨酸→谷氨」「神经元→经元」这类**跨词边界碎片**，因邻居恒定而熵为 0，被自动挡住                                                                                                                                                                                          |
| **英文筛词**         | 停用词 + 单位/试剂/编号（`min div kcl vpp e18 …`）+ 来源噪声词（`fulltext student …`）+ 统计泛词（`mean sem …`）                                                                                                                                                                                                                                                          |
| **受控范式标签**     | `paradigm_tags` **不切词上云**（`experimental / mechanistic / imaging …` 是 15 个固定标签，换谁都能打），改为单独统计并写进图注与报告                                                                                                                                                                                                                                   |
| **泛化词表**         | 中文`GENERIC_ZH`（`定量 参数 用于 时间 像素 计数 …`）+ 虚词边界规则（不成词的首/尾虚字）+ 泛化词头规则（`比较用` 类碎片）                                                                                                                                                                                                                                                   |
| **孤词门**           | **只来自方法描述**的词，至少要出现在 `--wc-min-docs`（默认 3）篇论文里；关键词/题名来源不受此限。一个只在一篇里出现的方法词，不构成这位作者的方法学特征                                                                                                                                                                                                                    |
| **布局引擎**         | 默认`--wc-engine=library`：**`wordcloud`（amueller）自绘**（v17.11）—— 布局与出图是同一个引擎，`to_image()` 出的位图直接 `imshow` 进 matplotlib 画布，**位置即所见**；标题/图注/方向图例仍由 matplotlib **矢量**叠加。v17.2–v17.10 的「库算布局 + matplotlib 复刻」已**实测证伪**（复刻与库栅格逐像素对齐：墨迹召回仅 64.2%），见 [实测结果汇总.md](实测结果汇总.md#k-10)                                    |
| **复刻层的两条硬条件（已随复刻层删除）** | ①**两边绑同一个字体文件**（`FontProperties(fname=…)` + 库的 `font_path`）：`.ttc` 集合里 matplotlib 可能选到与库不同的 face（常规体 vs 细体），字形宽度不同 → 复刻后**墨迹框大面积重叠**；绑定后降到个位数（数据见 [实测结果汇总.md](实测结果汇总.md#k-4)）。② **axes 物理纵横比必须等于布局画布比例**（1500:1100），否则纵向压缩、词会挤在一起。**②仍然必须遵守**（位图会被压扁）；①已无对象 |
| **坐标语义**         | `layout_` 存的是 **(y, x)**（库的 `to_image` 里写的是 `pos = (position[1], position[0])`）。**出图不再自己摆字**，只在 info/报告里读它做口径核对                                                                                                                                                                                                  |
| **放置口径**         | 报告与图注分开报三个数：**候选词型数** / **按权重取前 N 个** / **实际放下几个**。未放下的词带名字列出（`graph_data.json` 全量、报告前 10 个）。**「放下」必须数 `layout_`**，不能数 `wc.words_`（那是输入词频＝请求数，见 [实测结果汇总.md](实测结果汇总.md#k-12)）                                                                                                                                                                                    |
| **等宽英文字体**     | 纯 ASCII 词走**拉丁等宽**字体（Consolas → Cascadia Mono → Courier New → DejaVu Sans Mono，优先常规体），字距收紧 `WC_MONO_TRACKING=0.08×字号`。为什么**按词**切：CJK 字体的 ASCII 本就是半角定宽（SimHei 的 `i/M/W` 步进都 = 0.5 em），字母小、**看起来字距大**；换整份字体（NSimSun/MS Gothic）同样是半角格，而纯拉丁等宽字体没有中文。实现在 PIL 的 `text`/`textbbox` 入口按词替换（度量与绘制**同时**改），出图**必须走 `wordcloud_library_image()`** 才带得上补丁（自检 ⑭ 拦这条） |
| **字号比上限**       | `WC_LIB_FONT_RATIO=6`：最大字号 ≤ 6 × 最小字号（库把字号钳在 `[min,max]`，故成品实际比必然 ≤ 6；自检 ⑭ 断言）。**代价**：字号一压平，大词让不出位置、能放下的**词数陡降**（实测 min 8→348 词/比 2.0、**min 16→339 词/比 6.0/墨迹 26.2%**、min 32→95 词、min 40→65 词），故基准取 `WC_LIB_MIN_FONT=16` |
| **出图契约**         | 自检 ⑭ 断言：同权重两次渲染位图**逐字节一致**、位图非空、方向配色被采纳（`color_func`）、**等宽字体确已生效**（带/不带 mono 的栅格必须不同）。**代价如实申报**：词云 SVG **内嵌位图**（不再矢量字形）；PPT 用 PNG，不受影响                                                                                                                                                                                    |

> **关键词一致性**：报告、词云、可见方法节点与VOSviewer使用完整术语与来源门控。
> 内部方向相似度/冲突线索可保留启发式tokenize，但不得将其滑窗/散词直接作为展示或导出关键词。
> 词云core与方法画像的类别范围仍按三层规则分别处理。

**质检（「这一簇在讲什么？」「哪里在自相矛盾？」）**

| 问题             | 怎么答（**全部由数据聚合，不做语义臆测**）                                                                                                                                                                                           |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 这一簇在讲什么？ | `cluster_notes()` 汇总该簇的方向、方法范式、高频方法词、文献年份跨度与节点数                                                                                                                                                             |
| 哪里在自相矛盾？ | `find_contradictions()`：同方向内，**一篇的「待验证问题」与另一篇的「已验证结论」高度重合**（重合度 ≥0.30 且共同词 ≥4）→ 一篇说"还没解决"、另一篇说"已经证实"。**输出的是待复核线索，不是已确认的矛盾**，报告措辞严格区分 |

**格式要求（用户指定，已实现）**：

- **SVG 优先**，SVG 失败**自动退 PNG**；`--also-png` 可两者都要。
  **降级会留痕**：发生 SVG→PNG 降级的图，会在报告「字号自述」一节明写（下游 `ppt_brief.py` 只要 PNG，降级本身不影响 PPT，但"要矢量"就必须修）。
- ① **overview 画幅固定 16:10**（`16×10 in`；PNG 回退即 `4800×3000 @300dpi`）——
  与演示版面同比例，整幅铺放不出现上下黑边、也不用再被裁。
  该图**按画布原尺寸导出**（`save_fig(..., tight=False)`），
  **所有文字都必须画在画布内**，画到画布外会被直接裁掉。
- **产出尺寸 = 声明画布**：三张图都按画布原始尺寸导出（`save_fig(..., tight=False)`），
  不收起 tight bbox —— 否则产物宽度会与 `note_fonts` 的声明不一致，
  「字号自述」的换算基准就错了（词云曾因此被裁掉近五分之一的宽度，见
  [实测结果汇总.md](实测结果汇总.md#k-6)）。
  代价是**所有文字必须画在画布之内**，画到画布外会被裁掉。
- **高分辨率**（标准 = 清晰展示所有字符）——词云**布局与出图都由 `wordcloud` 完成**，
  长词/英文词的贴合按**真实字形**计算（自研版是按"CJK≈1.0 / ASCII≈0.55 字号"估的，
  估偏了就会压字）；位图分辨率跟 `--dpi` 走（300 dpi 下 scale≈2.46，位图 ≈3690×2706）。
- **背景透明**（`transparent=True`）。
- 中文字体自动探测（Microsoft YaHei / SimHei / Noto Sans CJK …）。
- **字号自述**：三张图都在 `graph_data.json` 的 `figure_notes` 里记录画布尺寸与全部字号，
  并换算到三个目标尺寸（幻灯片 16:9 / 论文双栏 183 mm / 论文单栏 89 mm）下的**有效最小字号**；
  低于 **5 pt** 只在 stderr 报 WARN 并写进报告 —— 幻灯片场景通常是够的，
  **要放进论文/报告排版才必须放大字号或缩小画布**。
  起因：方向聚类图在 17 in 画布上用 6 pt 标注，缩到 183 mm 只剩 2.54 pt，此前没有任何一步会发现。

**产出**：`<作者名>_知识图谱.md`（含三张图的说明、**overview 布局与阶段扇区自述**、
聚类解读、记忆连接表、冲突线索表、**词云取词口径与逐篇关键词采纳情况**、
**被剔除的词**、方向热点、**字号自述**）

+ `.work_cdp/graph/*.svg|png` + `graph_data.json`
  （含 `wordcloud.stats`、`figure_notes` 与 **`overview_layout`** —— 节点坐标与布局元信息）。

每篇文献每个术语最多计1次；边权为共同出现的文献数。map/network/thesaurus及审计文件
保留完整术语、源文证据、被拒词原因和空网络状态。聚类编号不预造，由VOSviewer计算。
没有可靠关键词时先补证据，不能退回任意中文n-gram/英文逐词散文凑词群。
既有 `--fulltext` 路线仅供受控词典原文匹配，不把滑窗候选直接导出。

> **共现阈值口径（`--min-doc` / `--min-occurrences`，默认 1）**：阈值=篇频下限。
> 小语料/高度专业化论文里绝大多数关键词是**篇内特异词**（仅 1 篇出现），
> 阈值 2 会剔掉约 95% 的词（实测 30 篇 149 词 → 8 词，阈值 3 → 空网络），
> 故**默认 1 保留孤立词**（VOSviewer 可显示孤立节点，map 中 `weight<Links>=0`）；
> `--max-terms`（默认 500）按篇频降序截断，大语料仍优先保留高频共现词。
> 要**聚焦跨篇共享的共现结构**时再显式调高（如 `--min-occurrences 2`）。
> 孤立节点多≠出错；空网络或仅孤立节点时不得宣称形成词群（见导出 README）。

> **诚实性约束**：挂不上方向的综述、放不下的低频词、不足 N 年的方向样本、
> 样本不足而不做热点簇着色的方向 —— 全部**显式报出数量或名字**，不静默丢弃；
> `--max-dirs` / `--max-review-nodes` 截断了多少也会打印；词云的关键词覆盖率、
> 被剔词型与剔除原因逐条落盘；右侧综述清单放不下时会写"余 N 条见报告"。
> 完整清单始终在《研究方向综述》里，图上只是节选。

> **确定性**：方向聚类的散点横向抖动用 **CRC32**（原用 `hash()`，而 Python 对 str 的
> 哈希默认按进程随机化 → 同一份数据每次跑出来的图都不一样）；Louvain 固定 `seed=42`；
> 径向整齐树、谱排序与 `adjustText` 都不含随机数。
> 阶段 K 的产出应当逐字节可复现。
