# 本流程：开发项目交接说明

> 本文是交接记录与操作清单。代码模块、文件树、模块依赖和公开 CLI 详见同目录 `开发项目说明.md`。权威阶段和政策以项目根目录 `SKILL.md` 为准。

## 1. 项目与接手范围

- 项目类型：本科生文献检索与科研辅助工作流，由 Agent/SKILL 编排、Python CLI、CDP 浏览器和文件产物共同组成；不是单体 Web 服务。
- 两条业务链：选题/找导师/领域概貌 `N → S → R → R2`；作者论文采集分析 `0 → A → B → C → D → D2 → E → F → G → G2 → H → H2 → K → P → I`。
- 接手第一步须确认本次是业务执行还是代码开发。业务执行一般不改脚本；开发变更需要定位模块、调用方、文件契约、测试与文档影响。
- 推荐先阅 `SKILL.md`、受影响子流程规范，再阅 `docs/开发项目说明.md` 的文件树、依赖关系和对应 CLI 接口表。
- 权威顺序：`SKILL.md` > 子流程 `SKILL.md` > `完整链路.md` 操作汇编 > `README_FOR_AGENTS.md`/历史记录。若有策略矛盾先停并按权威文件处理。

## 2. 首次接手检查

1. 确认项目根目录是 `本目录`，确认 Git 状态/未提交修改，不覆盖他人现有更改。
2. 读取 `README.md`、`README-PACKAGE.md`、`完整链路.md`，确认发行包与当前工作副本的路径差异。
3. 查清工作目录及已有日期/作者产物；`.work_cdp/`、浏览器 profile、cookie、日志、PDF 和缓存可能含敏感/真实数据，不得清理或复制到发行包。
4. 核实运行环境。项目推荐 Windows、`uv`、CDP 兼容浏览器；Bash 编排需 Git Bash。可先运行离线检查：

```bash
uv run python scripts/selftest_pipeline.py --offline
uv run python scripts/selftest_fallback_wiring.py
uv run python scripts/selftest_nature_integration.py
```

Windows 本地环境可检查：

```powershell
.\start_local.ps1 doctor
```

5. 若需要联网或浏览器实测，先确认目标站点、API 配额、工作目录和用户授权；离线自检通过不代表网络链路有效。
6. 运行命令前先运行 `uv run python scripts/<脚本>.py --help`，核实本地版本支持的参数、默认值和退出码。文档命令仅作为经源码核对的常用示例。

## 3. 按任务选择业务入口

### 3.1 选题、找导师、领域概貌

- N：Agent 从用户意向构造主题计划，不把主题对象错当方法分类。
- S：`scripts/harvest_faculty.py` 依据 `templates/学部官网源.json` 抓院系官网名单。运行完成必须停下等待用户选方向/导师；方向是粗分类，应保留官网原文和链接。
- R：可先用 `route_databases.py` 选择数据库；较大/可复现检索走 `search_plan.py → search_run.py → search_screen.py → search_report.py`。检索条数受 API 上限控制，必须保留 complete/截断状态。
- R/R2：`reviews_prepare.py → reviews_fulltext.py → Agent 子代理 → agent_poll.py/subagent_gate.py → reviews_build.py`。任务包、结果卡及原文路径需一一对应。

### 3.2 作者论文分析

- 从阶段 0 开始。先分项确认输出格式、翻译、反向参考文献、图谱、PPT、解读档位/引擎等选项，再写 `.work_cdp/prepare_plan.json`。
- 采集编排入口 `run_all.sh` 只负责作者数据采集主干，不意味着自动完成 F-I 全部分析阶段。
- 依序核实 ORCID、Crossref 题录和作者身份，之后才进入参考文献扩展、全文、翻译、解读、图谱或 PPT。
- Agent 任务由 `tasks/` 输入、`results/` 输出；不要混用不同批次或覆盖其他作者结果。

## 4. 开发变更交接要求

任何代码修改均需记录以下内容（按实际变更填写，不适用项注明“不适用”）：

| 项目 | 交接内容 |
|---|---|
| 需求来源 | 用户目标、明确约束、确认时间/确认项 |
| 修改文件 | 相对路径、模块名称、改动目的 |
| 对外接口 | CLI 参数、环境变量、Python 导入函数、文件/API schema 是否改变 |
| 依赖关系 | 直接调用方、被调模块、配置/Schema/模板影响、可选依赖变化 |
| 兼容性 | 旧数据/旧任务卡/历史目录是否兼容；迁移或回滚要求 |
| 风险边界 | 网络请求、CDP、隐私数据、API 限流或外部服务变化 |
| 测试证据 | 精确命令、退出码、关键结果、未覆盖项；不得只写“测试通过” |
| 产物位置 | 输出路径、是否新建/覆盖、是否含真实用户数据 |
| 后续事项 | 待用户确认、待联网验证、待更新版本记录或文档 |

**开发顺序**：先理解生产者和消费者 → 再改模块 → 同步 schema/配置/CLI 文档 → 跑专项离线自检 → 跑 `selftest_pipeline.py --offline` → 需要时安排小规模联网/CDP 验证 → 更新版本历史（仅行为/功能变更）。

**硬性规定（`SKILL.md` 文件头第 9 条）**：每次对脚本的重构/新增/删除**必须同步修改项目文档**（`SKILL.md` §8 与阶段节、`docs/开发项目说明.md` 文件树/模块边界/CLI 索引、本文件、受影响 schema/模板/子流程规范）。**全部项目文档只保留当前最新有效版本**，不累积版本叙述；版本沿革一律放 `版本变动.md`，实测证据放 `实测结果汇总.md`。`SKILL.md` 与 `README.md` 不写版本历史或实测运行数字。

## 6. 高风险处理

1. **全文访问**：严格按 `SKILL.md` §5.1。原文全文路径受 CDP 和批准的回退策略约束；元数据/摘要/综述题录的允许直连不代表允许抓取任意全文。
2. **站点限流/验证**：遵守 API 速率、站点熔断及 `SKILL.md` §5.2 人工交互政策；遇到限流/验证失败按规则停止或转人工，不自编绕过策略。
3. **事实准确性**：题录、作者归属、研究方向、引用数和全文都以来源记录为准；缺字段就保留缺失，不用模型推断补齐事实。
4. **目录安全**：先解析输出路径再运行写入脚本。不得把 `.work_cdp/`、`2026*` 日期数据、Cookie、模型权重、虚拟环境当成可随意删除的缓存。
5. **接口兼容**：JSON 字段、目录布局、退出码和 stdout/stderr 契约都属于调用接口。尤其 `prepare_stage.py --tier/--engine` 的 stdout 只用于返回枚举值，不能向 stdout 混入日志。
6. **计划与门控**：阶段 0 缺失计划时可选阶段应保守跳过。不能根据旧运行目录或旧确认记录猜本次用户授权。
7. **流程策略变更**：新增阶段/分支、改数据源或判据需在链路大阶段起点逐项确认，并记录到 `版本变动.md`。

## 7. 故障定位顺序

- 先保留完整命令、退出码、标准输出/错误和当前 workdir。
- 核对参数解析（`--help`）、输入路径/schema、工作目录/环境变量、依赖导入，再查看阶段日志与 `run_journal.jsonl`。
- 结合上下游检查契约，不只重跑报错脚本。全文路由尤其要核对 `cdp_failed`、阶段 0 `fulltext_fallback` 和白名单判定。
- API 429/超时先退避/停跑；不并发放大失败请求。
- 仅对受影响输入做小规模重现；不要将自检夹具写入真实数据目录。
- 记录最终根因、修复范围、测试结果和剩余限制，再交接给下一位维护者。
