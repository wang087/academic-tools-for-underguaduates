## 3. 每条的「为什么这么做」

### 3.1 P2-4 · JATS 判据抽成公共模块（`jats_fulltext.py`）

- **动机**：`reviews_fulltext.jats_body_stats()` 只服务于阶段 R，但「HTTP 200 + 完整
  `<pmc-articleset>` + 没有 `<body>`」这件事**与阶段无关**。Springer Nature 的 API
  返回的就是 JATS，若不判 `<body>`，一篇非 OA 的壳会被当成功写进交付物。
- **不重复造轮子**：语义与既有实现**逐字等价**，且 `--self-test` 里有一条**交叉验算** ——
  导入 `reviews_fulltext`，用同一份夹具比对两个实现 + 比对 `MIN_FULLTEXT_CHARS`。
  两处一旦漂移，自检立刻失败，而不是等下游读到假全文。
- **顺带补的一致性**：`SOFT_WRAP=1200` 与 `docs/阶段R全文获取模块.md` 五之⑤ 的落盘约定
  对齐；`write_fulltext_txt()` 的头部字段（`# source/# doi/# chars/# note`）与
  `download_all_fulltexts.save_fulltext()` 一致，便于下游统一解析。

### 3.2 P2-1 · 出版商 API（`fulltext_publishers.py` + `fulltext_credentials.py`）

**三重闸门，缺一不可**（任何一条不满足就拒绝发请求）：

1. **显式开关** —— `LIT_FLOW1_ALLOW_PUBLISHER_API=1` 或 config 里
   `allow_publisher_api: true`。默认**关闭**。
2. **可用凭据** —— 见 `fulltext_credentials.is_usable()`。
3. **DOI 归属** —— 前缀确实属于该出版商。

为什么坚持闸门：`fetch_oa_direct.py` 的双路径守卫（退出码 3）就是为了防「顺手直连出版社」。
本模块用一个显式开关达到同样效果，同时保留 API 这条合法路线。

几个刻意的取舍：

- **凭据只读**。立场与 `SKILL.md:1690-1697` 一致（不代填、不代登录、不代持）。写入交给
  外部 skill 的 `configure_credentials.py`（它已实现 0600 + 原子写），重复造一份只会多一条
  泄露面。读取路径与它**兼容**（`LIT_DL_CONFIG_DIR` 或 `~/.config/lit-dl/credentials.json`），
  也可用 `LIT_FLOW1_CREDENTIALS` 覆盖。
- **IEEE 缺 endpoint 模板时显式拒绝**。Metadata key 不是收费全文权限 —— 这条不判会把
  「查得到元数据」误当「下得到全文」。
- **Springer 的 key 走查询参数**，这是接口事实。因此该分支被单独标出
  （`secret_in_url=True`），且 URL 一律经 `redact_url()` 才允许进日志/manifest/结果。
- **落盘前先过判据**。JATS 分支先 `is_real_fulltext()`，不通过就**不写盘**（自检有专门断言
  验证「壳未落盘」）。
- **不做 PDF 页数校验**。那归 `store.validate_pdf`（`SKILL.md:1686` 硬约束），本模块只做
  **格式嗅探**，两者职责不同。

### 3.3 P2-2 · OA 候选瀑布（`oa_candidates.py`）

**默认只清点、不下载。** 因为：

- 「用 Unpaywall 判断哪篇有合法 OA 副本」属**第一层**（白名单里 `api.unpaywall.org` 是
  `content_class: metadata`）；
- 但「取原文全文（含 OA）」属**第二层**，`fetch_oa_direct.py` 已用守卫堵死。

所以本模块把**判断**做全、做可审计，把「要不要真的取」留成显式动作。即便显式取回，
**每个候选仍要过 `white_list_policy.decide()`** —— 自检里有一条专门验证
「出版社域名的 OA 候选被拦为 `route_disabled`（`next=browser`）」，即
**不因「它是 OA」而放宽分层**。

技术要点（对应 nature-downloader 的优势项）：

- DOI → PMCID 自动补全（这正是阶段 R 曾经**整批漏采**的那一步，见
  `docs/阶段R全文获取模块.md` 一）；
- PMC OA 清单只收 `format` 含 pdf 的链接（tgz 混在里面，当 PDF 存下来会得到
  「体积达标但内容错」的假成功），并把 `ftp://` 改写为 `https://`；
- Unpaywall 保留 `host_type` / `version` / `license`（供后续合法性分类）；
- **候选排序**而非先到先得：PMC(0) → Unpaywall(1) → publisher_oa(2) → repository(3) →
  arXiv(4)，同级 PDF 优先；
- **三态结论**：`confirmed_oa` / `confirmed_closed` / `unknown`，
  `unknown` **绝不**被当作非 OA；
- **没有真实联系邮箱就不查 Unpaywall** —— 占位邮箱等于没有邮箱，且会把无效流量算进
  别人的 polite pool。原因会明写进审计输出。

### 3.4 P2-6 · `content_class` 的运行时消费（`white_list_policy.py`）

这是对照报告 §7.1 第 1 条那个缺口：`content_class` / `oa_only` **只被
`fetch_direct.py --self-test` 读**，运行时没有消费者。现在它们有了：

```python
from white_list_policy import decide
d = decide("https://www.ebi.ac.uk/europepmc/webservices/rest/PMC1/fullTextXML",
           "fulltext", is_oa=True)
d["allowed"]   # True
```

语义要点：

- 请求层级与允许层级是**包含**关系而非相等：请求 `abstract` 而该源允许到 `fulltext`
  是允许的；反之是越界。
- `oa_only=true` 的源**必须**由调用方声明 `is_oa=True`；**不声明就拒绝** ——
  宁可少拿一篇，也不越界取一篇非 OA 正文。
- 未知请求层级**拒绝**，不接受默认值。
- 域名匹配**复用** `fetch_direct.domain_allowed()`（后缀边界，防
  `api.crossref.org.attacker.com` 陷阱），不重写。
- `audit_whitelist()` 把 `fetch_direct --self-test` 的三条策略断言变成可复用函数
  （不得含出版社内容站 / `content_class` 合法 / 含全文 XML 必须 `oa_only`）。

### 3.5 P2-3 · 节流与跨轮熔断（`fetch_pacing.py`）

补的是三条落差（对照报告 §1.5）：

- 既有 `pace()` / `HostPacer` 是**各自一份私有实现**，新路线无从复用；
- `SiteGuard` **只在进程内**，跨轮不复用 —— 新一轮会重新撞同一堵墙；
  而 `README.md:811` 承诺的「永久跳过」在代码里没有对应实现；
- 新模块若自建一份状态文件就会与既有状态漂移。

做法：

- **不新立状态文件**。熔断状态写进既有 `fulltext_state.json` 的 `_sites` 保留键
  （键名以 `_` 开头，既有代码逐 DOI 遍历，不会碰它），且**读-改-写** ——
  自检有一条专门断言「写熔断状态后逐篇 `pdf_ok` 结果完好」，因为整文件覆盖会毁掉断点续传。
- **间隔表按实测**：出版社内容站 120–240s（Elsevier/AACR 实测档位）、
  结构化 API 5–12s、未知站点回退 25–55s（宁可慢，不可打封）。
- **别名表**把 `detect` 的出版社组键（`elsevier` / `wiley` / `nature.com`）映射到域名档位，
  否则按 DOI 推定站点时会掉进默认档。
- **漂移断言**：自检比对 `DOI_PREFIX_SITE_SUPPLEMENT` 与
  `detect._DOI_PREFIX_SITE`，冲突即失败。补充的 6 个前缀
  （`10.1158` / `10.4049` / `10.1109` / `10.1136` / `10.1001` / `10.1056`）是 `detect`
  未覆盖的，已明确列出。
- **两条不变量**在文档与自检里都写死：① 同站点严格串行；② 记账必须在站点锁内
  （自检用 6 线程 × `limit=3` 验证恰好放行 3 个）。

### 3.6 基础类型（`fulltext_result.py`）

三条状态语义**固化进类型**，而不散落在字符串里：

```text
SUCCESS  拿到了可用产物
HANDOFF  **不是**最终失败：需要用户或另一条路线接手（carsi_*、api_not_entitled 等）
FAILURE  本条路线走不通，重试也不会变好
```

未知状态一律按 `FAILURE`（fail closed）。`to_dict()` 是唯一出口，出口即脱敏 ——
URL 里的秘钥参数、秘钥类请求头都出不去（自检逐条验）。

其中一条自检值得单独说：`has_secret_in_url()` 与 `redact_url()`。
最初用 `url != redact_url(url)` 判断「URL 是否带秘钥」，结果把
`api.elsevier.com` 路径里 `10.1016/...` 被百分号编码成 `%2F` **误报**成带秘钥。
现在改为按查询参数名判定，并加了回归断言；`redact_url()` 在无秘钥时**原样返回**，
不改写编码。

### 6.1 主链路接线：把新模块接进 `download_all_fulltexts.py`

| 接线点 | 改法 | 风险 |
|---|---|---|
| 熔断器替换 | `SiteGuard` → `PacerGuard`（拿跨轮持久化） | 状态文件多一个保留键；既有 `--status` 输出不变。**低风险** |
| 节流替换 | `pace()` → `pg.pace(site)` | 间隔表比现值更细（出版社站从 25–55s 提到 120–240s）→ **会明显变慢**，但正是实测需要的档位 |

| 状态语义 | `pdf_error` 自由文本 → `FullTextResult` 的 typed status | 会改 `fulltext_state.json` 的字段，`inventory_build.py` / `reviews_fulltext.py:651-658` 在读它。**中风险** |

**建议顺序**：先只接熔断持久化 + 节流（低风险、纯收益），状态语义改造单独一轮。

### 6.3 OA 候选是否允许「直连取正文」

这是**唯一一个纯立场问题**。当前 `oa_candidates.fetch_candidate()` 会逐候选问
`white_list_policy.decide()`：

- 若 `api.unpaywall.org` / `www.ebi.ac.uk` 这类**已在白名单**的源 → 允许直连；
- 其他（PMC 网页、repository、出版社 OA）→ `route_disabled` + `next=browser`。

**需你决定**：

| 选项 | 含义 | 后果 |
|---|---|---|
| **A（当前默认，最保守）** | 只有白名单内源能直连；其余一律走 CDP | 与 §5.1 完全一致；但 PMC OA 的 pdf 直链（`ftp.ncbi.nlm.nih.gov`→https）会被判越界，需走 CDP 才拿得到 |
| B | 把「OA 候选直链」整体登记为第一层（按收录三判据改 `templates/直连白名单.json`，声明 `oa_only: true`） | 需先过 `fetch_direct.py --self-test`；等于**放宽**现行分层，必须你明确点头 |
| C | 保持 A 的判据，但把「已确认 OA」的直链取回交给 CDP（即 `oa_candidates` 只出清单，取回全归 `download_all_fulltexts.py`） | 折中：清单能力用上，分层不动。**改动最小** |

> 我倾向 **C**：它拿到了 P2-2 的全部判断价值（PMCID 补全、候选排序、三态结论、

### 6.4 SI（补充材料）采集
