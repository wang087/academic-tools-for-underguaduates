# 本流程：开发项目说明

> 本文依据项目当前目录、`SKILL.md`、`README_FOR_AGENTS.md`、`完整链路.md`、依赖清单及运行脚本整理。它是开发者视角的项目地图，不替代权威操作规范。发生冲突时，以 `SKILL.md` 为准。参数表按源码当前 CLI 定义整理，脚本更新后应同步核对。

## 1. 项目概览

“本流程”是面向本科生的文献检索与科研辅助工具，组合了 Agent/SKILL 编排、Python 数据处理脚本、CDP 浏览器获取正文和本地/远程子代理解读。它不是单一 Web 服务或单一 Python 包，而是一套以文件系统产物和阶段契约连接的工作流。

主要面向两类任务：

1. 本科科研选题前置链路：研究意向 → 主题与关键词计划 → 学部导师名单与粗分类 → 多源综述检索 → 领域概貌。
2. 作者论文分析链路：准备计划 → 作者/ORCID 定位 → 成果采集与题录核实 → 同名消歧 → 参考文献扩展 → 全文获取 → 翻译/解读/综述/知识图谱/PPT（按用户确认选择）。

项目定位是实验性质的科研辅助工具，不对检索覆盖率、论文元数据或结论可靠性作保证；最终使用者必须核查原始主页和论文全文。

## 2. 技术组成

- 编排层：`SKILL.md`、子流程 `SKILL.md` 和模板，定义阶段顺序、停顿点、提示词与质量门。
- 流程层：`scripts/` 下的 Python 命令行脚本；多数脚本围绕明确阶段工作，使用 JSON/Markdown/PDF 等文件交接。
- 数据源：ORCID、Crossref、OpenAlex、Europe PMC、PubMed、arXiv 等元数据/API；学校院系公开师资页面。
- 全文获取：CDP 控制的 Chromium/Edge 浏览器；原文正文必须遵守 `SKILL.md` 的分层获取政策。
- 解读/生成：Agent 子代理生成结构化解读卡；本地脚本做校验、汇总、制图与文件导出；可选 PPT 集成依赖放在 `vendor/`。
- 本地模型：`scripts/small_model.py` 与 `selftest_small_model.py` 是可选的模型工具链；模型 Python 环境单独配置，不属于核心解释器依赖。

## 4. 流程关系与阶段职责

### 4.1 本科科研辅助前置链路

| 阶段 | 主要责任 | 主要输出/停顿 |
|---|---|---|
| N | 从口语意向提取 school/unit/topic/level、主题词和方法词 | `.work_cdp/topic_plan.json`；通常不反问用户 |
| S | 从学校/学部官网抓导师，保留主页原文并按关键词粗分类 | 导师名单、JSON；必须停下等用户选择 |
| R | 按方向选择数据库，优先取综述题录并报告检索边界 | 综述候选与来源记录 |
| R①/R①.5 | 组装综述任务包，按政策取全文并回填文本 | `reviews/tasks/` 与全文/文本字段 |
| R2 | Agent 并行精读，汇总本科生可读领域概貌 | `领域概貌.md` 与解读卡 |

本科入门任务通常可在 R2 交付，不必自动进入作者论文链路。

### 4.2 作者论文分析链路

权威顺序为 `0 → A → B → C → D → D2 → E → F → G → G2 → H → H2 → K → P → I`。阶段是否运行由阶段 0 的准备计划决定；PPT、翻译、参考文献扩展等均按明确确认和闸门执行。不要把 `run_all.sh` 当作所有阶段的一键完成器：它主要编排采集阶段，后续阶段仍由对应脚本与 Agent 按规范运行。

| 阶段范围 | 责任概括 | 常见关键产物 |
|---|---|---|
| 0 | 收集独立选项并建立阶段闸门 | `.work_cdp/prepare_plan.json`、运行流水 |
| A-C | 作者定位、浏览器环境、ORCID 成果集 | ORCID JSON、DOI 清单 |
| D/D2 | Crossref 核验、作者同名消歧、参考文献反向扩展 | 核验后题录、参考文献池/综述网络 |
| E | 获取正文并校验 PDF/HTML | `<作者>_paper_Exports/`、下载日志 |
| F/G/G2 | 翻译、论文目录、代表论文参考文献 | Markdown/PDF/参考文献清单 |
| H/H2 | 单篇论文解读及方向综述 | `interpret/tasks/`、`results/`、汇总报告 |
| K | 知识结构图、词云、方向聚类和导出 | 图像/SVG、结构化图数据、审计信息 |
| P | 可选 PPT 项目生成 | PPT 项目目录、PPTX 与校验结果 |
| I | 收尾与交付核验 | 完整交付清单、运行记录 |

## 5. 数据与脚本契约

- 阶段数据以文件交接，不假定跨阶段共享 Python 进程状态。JSON 字段名、输出目录与文件名是下游接口的一部分。
- `.work_cdp/prepare_plan.json` 是阶段 0 选择的单一事实源；`run_journal.jsonl` 用于审计阶段确认和执行。不要只改控制台参数而忽略计划文件。
- Agent 解读任务按 `tasks/` 和 `results/` 隔离；每个子代理只处理自己的任务，主控负责轮询、汇总和结构/内容质量门。
- DOI、作者、单位、年份等身份信息通过运行参数或 `PAPER_*` 环境变量提供；不得把历史案例值写成默认配置。
- 抓取结果和合成自检数据必须区分。真实运行输出常落在日期目录/作者子目录；自检应优先使用临时目录。
- 当前脚本索引以 `SKILL.md` §8 为准；目录中存在大量子流程、实验和自检脚本，不要仅按文件名推断其是否为生产入口。

## 6. 环境与依赖

推荐 Windows 环境；流程文档同时使用 Bash/Git Bash 与 PowerShell。作者采集链路依赖 Chromium 兼容浏览器及 CDP。Python 命令优先使用项目文档声明的 `uv run`，本地入口可用 `start_local.ps1`。小模型权重和模型环境独立配置，不应与核心依赖混装。

- `requirements-core.txt`：PDF、CDP、网络请求、schema 等核心依赖。
- `requirements-browser.txt`：在核心依赖上增加 Playwright/OpenCV/psutil。
- `requirements-visual.txt`：图谱和视觉生成依赖；具体清单以文件为准。
- `requirements-ppt.txt`：PPT 可选依赖。
- 网络需求因阶段而异；离线自检不等于联网采集可用。
- 可选解析层（分层共存，非核心依赖）：opendataloader 轻量层已整合进 `vendor/opendataloader/`，需本机 **Java 11+**（无 Python 依赖）；MinerU 深解析层为环境级可选，首跑由 `optional_layers.py` 探测并询问用户是否安装。两者都不影响 fitz/pypdf 主链路。

建议首次接手仅先执行离线自检：

```bash
uv run python scripts/selftest_pipeline.py --offline
```

再按需要运行专项测试，例如 `selftest_engines.py`、`selftest_fallback_wiring.py`、`selftest_vosviewer_pipeline.py`、`selftest_nature_integration.py`。联网自检会受外部 API、限流、网站结构变化影响。当前文档还列有 Windows 本地入口：

```powershell
.\start_local.ps1 doctor
```

## 7. 安全与合规约束

1. 以 `SKILL.md` §5.1/§5.2 为准：元数据/摘要/综述题录和白名单源按规则处理；原文全文按规定走 CDP，第一层失败按流程回退。
2. 禁止对规则列出的出版商内容站进行绕过策略的直连探测或全文抓取。不得通过改写脚本绕开访问控制、验证或频率限制。
3. arXiv 等服务需尊重官方速率限制；遇到 429/限流按规则减速或停止，不用替代解析绕过。
4. 若需宿主机级人工交互，遵循 `SKILL.md` 当前次数上限、失败即停和人工接管政策；其他说明文档的旧限制不作为依据。
5. `.work_cdp/`、CDP profile、cookie、日志和作者数据可能含个人信息/访问凭据。对外分享前审查并排除，不应打包用户数据或浏览器会话。
6. 阶段流程、判定标准或抓取策略变更属于行为变更：先说明范围并获得用户同意，再修改并更新 `版本变动.md`；不要把运行实测数据写入 `SKILL.md`。

## 8. 维护约定与建议

- **脚本改动必须同步项目文档（硬性，见 `SKILL.md` 文件头第 9 条）**：每次对 `scripts/` 及随包模块的重构/新增/删除，必须同步更新 `SKILL.md` §8 脚本索引与相关阶段节、本文件的文件树/模块边界/CLI 索引/依赖说明、`docs/项目交接说明.md`（涉及时）及受影响 schema/模板/子流程规范。**项目文档只保留当前最新有效版本**，不累积版本叙述；版本沿革只记入 `版本变动.md`，实测数据只记入 `实测结果汇总.md`。
- 先读权威 `SKILL.md`、受影响子流程规范和脚本，再改实现；按“输入/输出/schema/目录/日志/闸门/异常退出”逐项核对上下游契约。
- 规则变化同步对应模板/schema、自检与版本记录；仅文档整理不应虚构版本或实测。
- 修改脚本后先跑专项离线测试，再跑 `selftest_pipeline.py --offline`；涉及网络或浏览器的变化增加可控专项验证，不在未获确认时启动大规模抓取。
- 对新数据源先做路由/白名单/节流设计与可追溯性验证，不把临时实验脚本直接当成正式流程。
- 避免将缓存、虚拟环境、模型权重、真实运行产物和源代码混淆；项目树中 `.work_cdp`、`.venv`、模型缓存与发行源码应分别管理。

## 9. 已知限制

- 外部站点结构、反自动化策略和 API 字段会变动，导师页面抓取与全文获取需要持续抽样核验。
- 搜索结果常受 `max-records`、`max-calls` 等上限截断；`complete=false` 时只能表述为部分检索结果。
- 导师关键词分类是粗分类，可能一人多类；必须保留来源链接并由用户判断。
- 元数据缺失、作者同名合并、全文缺页/解析失败会传导至解读与图谱；各阶段报告应保留缺失和失败清单。
- 仓库含实验性、可选及随包 vendor 代码；仅凭文件存在不能推断该功能已在当前机器配置或全链路验证。

## 11. 模块依赖关系与数据流

```text
SKILL.md + 阶段确认
        │ 定义允许的流程、分支和门控
        ▼
prepare_stage.py ──写入──> .work_cdp/prepare_plan.json
        │                       │ --check / --tier / --engine
        ├───────────────┬───────┘
        ▼               ▼
N/S/R/R2 链路       作者论文 0-A-I 链路
N: topic_plan       ORCID → Crossref → disambiguation
S: harvest_faculty       │
R: route/search/paginate │ D2 refs_backfill / G2 bibliography
R①: reviews_prepare     ▼
R①.5: reviews_fulltext  E: CDP/browser → PDF/HTML/text
R2: task JSON           ├─ F translation
        │                ├─ H/H2 task → subagent results → quality gate/build
        │                ├─ K graph / keyword export

```

具体依赖传递：

- `prepare_stage.py` → `logutil.py`, `run_status.py`；本地写计划，不联网。下游阶段通过 `PAPER_WORKDIR` 定位同一工作目录，再通过 `--check <阶段>` 消费闸门。
- `harvest_faculty.py` → `templates/学部官网源.json` + `faculty_discover.py` + `faculty_engines.py` + `faculty_dom.py`；按站点配置选择列表解析/详情解析，渲染或交互型页面再依赖 `faculty_render.py`/`faculty_interact.py`。
- `search_plan.py` → 生成计划 JSON；`search_run.py` → `skills/paper-lookup/scripts/paginate.py`；`search_screen.py` → 筛选与可得性；`search_report.py` → PRISMA 报告。它们通过同目录计划/结果 JSON 连接。
- `reviews_prepare.py` → 将 R 阶段记录归一成 `tasks/*.json`；`reviews_fulltext.py` → 更新全文字段/`fulltext_path`；Agent 读取 tasks 并写 `results/*.json`；`agent_poll.py`/`subagent_gate.py` 负责进度和质量状态；`reviews_build.py` 只汇总通过门控的卡。
- 作者链路中 `orcid_*` → Crossref fetch/retry/enrich → `disambiguate.py` → `scope.py` 给下载和著录共用排除口径；`refs_*` 消费已核实题录；`interpret_prepare.py` 消费题录、摘要与本地 PDF 抽取文本，支持 `--tier=L1|L2|L3`、`--engine=legacy|paper-card`、`--max-chars=N`、`--only=DOI,DOI`、`--no-text`、`--limit=N`（`-h/--help` 查看说明）；`interpret_build.py` 汇总结果卡。
- `cdp_pool.py` → `cdp.py` + `browser_runtime.py` + `logutil.py`，对目标 workdir 下浏览器实例做启动/状态/回收。可选全文模块不等于 browser pool；主链路启动与生命周期管理仍由核心模块负责。
- `fulltext_router.py` → 白名单策略、候选路线、凭据策略、节流、JATS 转文本及状态模型；必须满足其守卫前置条件，不可当成通用下载器。
- `knowledge_graph.py`、`vosviewer_export.py`、`keywords_three_layer.py` 消费 H/H2 结构化卡与 tasks；知识图谱依赖 `requirements-visual.txt` 中的绘图库，VOSviewer 文本导出主要为本地转换。
- `nature_bridge.py` 将 `vendor/nature-paper-card` 能力收敛到单一接口，并负责结构/内容质量校验；PPT 通过 `ppt_brief.py` 汇入既有报告、图表和 `vendor/ppt-master`。

统一从**本流程根目录**（含 `SKILL.md`、`scripts/` 的目录，文件夹名不限）执行，所有路径均为相对该目录的相对路径。Python 命令的推荐形式是 `uv run python scripts/<脚本>.py ...`；也可按 `README-PACKAGE.md` 的发行目录方式执行。此索引列出主要公开 CLI，不替代参数解析器；不确定参数或版本变化时先运行 `--help`。`prepare_stage.py` 使用自定义参数读取器，没有通用 `--help`，应看本节参数说明和脚本内置用法，或执行只读的 `--audit`。尖括号内容为占位符，不应原样复制。

#### 13.5.1 图谱与 PPT 参数补充

`knowledge_graph.py` 读取阶段 H/H2 最终产物，本地处理、不联网；除非已在阶段 0 逐项确认，否则不能启用 `--kw-model`。常用参数均采用 `--name=value` 形式：

| 参数 | 默认/取值 | 用途 |
|---|---|---|
| `--recent-years=N` | 默认 3 | 方向时间线窗口 |
| `--max-reviews=N` | 默认 3 | 每方向挂接综述上限 |
| `--dpi=N` | 默认 300 | PNG 输出分辨率 |
| `--format=auto|svg|png` | 默认 auto | 输出格式；auto 为 SVG 优先并允许回退 |
| `--formats=svg` | 可选 | 只出 SVG |
| `--also-png` | 关闭 | 在 SVG 外额外生成 PNG |
| `--max-dirs=N` / `--max-review-nodes=N` | 默认 12 / 24 | 方向数与综述节点上限 |
| `--wc-lang=both|zh|en` | 默认 both | 词云语言 |
| `--wc-engine=library|custom` | 默认 library | 词云布局实现；library 需要 wordcloud |
| `--wc-min-docs=N` | 默认按脚本常量 | 方法描述关键词最低篇数 |
| `--wc-weight-keywords=N` 等 | 默认 keywords=3/title=2/abstract=2/methods=1 | 控制词源权重；支持 `--wc-weight-key_20=N` |
| `--kw-model` | 关闭 | 使用独立 kw LoRA 小模型精筛，需阶段 0 明确确认 |
| `--strict-fonts` | 关闭 | 字号不足时转硬失败 |
| `--self-test` | 可选 | 逻辑自检 |

示例：

```bash
uv run --with matplotlib --with networkx --with python-igraph --with adjustText --with wordcloud python scripts/knowledge_graph.py --recent-years=3 --format=svg --also-png --wc-lang=both
```

`ppt_brief.py` 的参数是 `--name=value` 或布尔开关：`--ppt-dir=PATH`、`--outdir=PATH`、`--project-name=NAME`、`--title=TEXT`、`--pages=short|standard|long`、`--canvas=ppt169`、`--lang=zh-CN`、`--dry-run`、`--no-graphs`、`--check-svg=PATH`、`--self-test`。默认读取阶段 0 页数选择，并在 `$PPT_MASTER_DIR` 或随包 `vendor/ppt-master` 查找依赖；PPT 的风格/画布等用户选择必须按阶段 P 规范确认。

其他阶段工具完整索引见 `SKILL.md` §8。尤其全文校验 `verify_pdfs.py`、批量抽取 `extract_parallel.py`、翻译渲染 `render_html_pdf.py` 参数较多，执行前运行 `uv run python scripts/<脚本>.py --help` 并按各阶段规范调用。

### 13.6 Windows PowerShell 启动器

.\start_local.ps1 doctor

首参 `Script` 默认 `doctor`；命名开关 `-Model` 切换到 `SMALL_MODEL_PYTHON` 或脚本自动发现的独立模型解释器；剩余参数原样传给目标 Python 脚本。普通模式用项目 `.venv/Scripts/python.exe`。doctor 会导入核心 PDF/CDP/图谱依赖，缺 `.venv` 或依赖时报错退出。

### 13.7 可选解析层（分层共存）

```bash
uv run python scripts/optional_layers.py probe [--json]      # 首跑探测 + 体积/损益/建议
uv run python scripts/optional_layers.py record --mineru-install=yes|no|defer [--note=TEXT]
uv run python scripts/optional_layers.py status
uv run python scripts/optional_layers.py --self-test
uv run python scripts/opendataloader_extract.py "<pdf>" [--out DIR] [--format markdown,json] [--image-output off]
uv run python scripts/opendataloader_extract.py --detect [--json]
uv run python scripts/opendataloader_extract.py --self-test
```

- `optional_layers.py`：只读探测 + 本地落盘，不联网、不代装。子命令 `probe`（默认）/`status`/`record`/`--self-test`。首跑判据＝无产物目录（`*_paper_Exports`/`*_Exports`/`outputs`）＋无 `.work_cdp`＋环境无 MinerU；`probe --json` 的 `should_ask_mineru_install` 标明是否需向用户发问，`mineru_advisory` 给出体积/损益/建议。`record` 写 `.work_cdp/optional_layers.json`（schema `optional-layers`）并记 journal；记录后不再追问。退出码 probe/status/self-test 0；record 0=落盘、2=取值错误。
- `opendataloader_extract.py`：`vendor/opendataloader/` 的唯一 adapter，需 Java 11+。jar 发现＝`OPENDATALOADER_JAR` > `vendor/opendataloader/*.jar`。默认输出 `.work_cdp/odl/<主干>.md/.json`（JSON 逐元素含 `bounding box`/`page number`/`type`）。本地模式无 OCR。退出码 0=成功、1=解析失败、2=缺 Java/jar 或用法错误；`--detect` 0=可用、3=不可用。
- 两脚本均不替换 fitz/pypdf 主链路（`prep_paper.py`/`extract_parallel.py`）；深解析（扫描件/表格/公式）走 MinerU，不在 opendataloader 本地模式范围。
